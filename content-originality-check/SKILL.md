# 内容原创性自检（防低创作度）

在**选题 → 写作 → 发布前**三个环节，把稿件对照平台「低创作度」红线做诊断与改稿，产出一版去 AI 味、有真实信息增量、观点主体是作者本人的内容。

## 何时使用

- 稿件要发布之前（建议作为发布流程的固定一环）。
- 用户说「过一遍原创性」「看看会不会被判低创作度」「发布前自检」。
- 用户说「去 AI 味」「humanize」「让文字更像人写的」：可只执行去味部分（步骤 4 + 模式库 + 评分）。
- 选题阶段：用户想确认某个选题是否属于饱和赛道。
- 收到平台「低创作度 / 内容质量」判定，需要复盘或指导后续写作。

## 四条红线与轻重分级

问题越靠上越重、越要早介入；文风问题最轻，改起来最快。

| 红线 | 典型表现 | 层级 | 处理方式 |
|------|---------|------|---------|
| 1. 同质化 | 题材/角度全网泛滥（如「纳瓦尔财富公式」「Notion 效率系统」），无信息增量 | 选题层（最重） | 换差异化切口，或放弃选题 |
| 2. 搬运 / 洗稿 / 大篇幅引用 | 全文是「某某说 X → 我理解 Y」骨架，观点主体是别人的 | 结构层（重） | 重构：把观点主体换成作者 |
| 3. 信息量不足 | 泛泛而谈，无数据、案例、可验证细节 | 内容层（中） | 补不可复制的料 |
| 4. 低价值 AIGC | 通篇机器节奏（见模式库） | 文风层（轻） | 去味轻改 + 注入个性 |

## 两个快速测试（先做，再逐段诊断）

1. **抽走引用测试**（测红线 2）：把所有转述他人观点/项目的段落删掉，看剩下的能否独立成文。剩余不足六成 → 观点主体是别人，必须重构，只去味救不了。
2. **指纹密度测试**（测红线 4）：抽查任意三段，若几乎每段都有加粗金句、破折号补刀或三连排比 → AI 指纹超标，需全文去味。

## 去 AI 味 · 五条核心原则

1. **删除填充短语**：去掉开场白和强调性拐棍词（「值得注意的是」「在这个时间点」）。
2. **打破公式结构**：避免二元对比、戏剧性分段、修辞性铺垫后揭示。
3. **变化节奏**：长短句混合；两项优于三项；段落结尾方式多样化。
4. **信任读者**：直接陈述事实，不软化、不辩解、不手把手解释隐喻。
5. **删除金句**：听起来像可引用语录的句子，重写它。

完整模式库（含前后对照示例）在 `references/ai-patterns.md`，执行步骤 1 诊断和步骤 4 去味时**必须读取**该文件逐类对照。

## 执行步骤

### 0.（选题阶段，可选）同质化预检
- 用 web 搜索选题关键词，看同题内容的数量与角度；若已饱和，帮用户找一个没被写过的切口，或建议换选题。

### 1. 诊断：输出诊断报告
- 先做两个快速测试，给出整体判断：这篇是「去味即可」还是「需要重构」，并说明依据。
- 再逐段对照四条红线和模式库，按固定格式输出，**必须指到原句**：命中红线/模式 → 原文段落/句子 → 轻改或重构 → 具体改法。

### 2. 重构观点主体（红线 1/2）
- 把主语从「别人/通识」换成「我」：用作者自己的系统、实测数据、真实案例去验证或反驳，而不是复述。
- 他人观点/热点项目从「开场主角」降为「一句引子」，引用篇幅压到全文 **20% 以内**。

### 3. 补不可复制的料（红线 3）
- 全文至少 **3 处**只有作者才拿得出的具体信息：真实数字、截图、一次真实复盘/决策的原文片段、失败经历。
- 只用真实素材；缺料时去查稿件库数据、复盘页、GitHub 记录，或直接问用户要——**绝不编造数据或经历**。

### 4. 去 AI 味（红线 4）
- 读取 `references/ai-patterns.md`，按「五条核心原则 + 模式库」逐类清理，同类句式全文 ≤ 2 处。
- 清理后按模式库中「去味 ≠ 有灵魂」一节检查，把作者的观点、语气、具体感受放回去。

### 5. 交稿前体检：快速清单 + 质量评分

快速清单：
- 连续三句长度相同？打断其中一个。
- 多个段落都以简洁金句收尾？变换结尾方式。
- 「——」后面跟着揭示或升华？删掉。
- 段首频繁出现「此外/然而」等连接词？考虑删除。
- 三段式列举？改两项或四项。
- 解释了隐喻？相信读者。

质量评分（改后自评，总分 50）：

| 维度 | 评估标准 |
|------|---------|
| 直接性 /10 | 直接陈述事实还是绕圈宣告？10 分直截了当，1 分充满铺垫 |
| 节奏 /10 | 句子长度是否变化？10 分长短交错，1 分机械重复 |
| 信任度 /10 | 是否尊重读者智慧？10 分简洁明了，1 分过度解释 |
| 真实性 /10 | 听起来像真人说话吗？10 分自然流畅，1 分机械生硬 |
| 精炼度 /10 | 还有可删减的内容吗？10 分无冗余，1 分大量废话 |

标准：45–50 分可交稿；35–44 分仍有改进空间；低于 35 分重新修订。

### 6. 复核与沉淀
- 通读改后版本：确认没有引入新的排比/金句堆叠；独家料 ≥ 3 处；引用 ≤ 20%。
- 发布前场景：把本次诊断结论（命中红线、改法、评分）追加到稿件页末尾（如稿件在 Notion，可用 `ntn pages update` 追加一个「📋 发布前自检记录」区块），方便日后复盘同类问题。

## 完成标准

- [ ] 已完成两个快速测试，并给出「轻改 / 重构」的整体判断。
- [ ] 诊断报告指到具体段落原句，不泛泛而谈。
- [ ] 观点主体是作者本人，引用篇幅 ≤ 20%。
- [ ] 独家料 ≥ 3 处，且全部真实、未编造。
- [ ] 已按模式库逐类清理，同类句式全文 ≤ 2 处，对话残留为零。
- [ ] 改后保留了作者的观点与语气，不是无菌文。
- [ ] 快速清单全过，质量评分 ≥ 45（未达标需说明原因）。
- [ ] 发布前场景：自检记录已沉淀到稿件页。
